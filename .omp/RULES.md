# MainSpot — reglas permanentes OMP para el entorno local

- **URL canónica, exacta e invariable del entorno local:** `https://app.mainspot.local.io`. Atención: es **mainspot**, nunca `mainpot`.
- Toda invitación de desarrollo, enlace de panel, enlace de vista previa, reporte dirigido al propietario y prueba E2E de navegador debe utilizar **`https://app.mainspot.local.io`** (incluido el origen / base URL de configuración).
- **Infraestructura ya definida:** `/etc/hosts` del host: `10.209.99.101 app.mainspot.local.io`; proxy HTTPS de confianza local en LXC `webserver` (`10.209.99.101`) hacia el servicio Express de MainSpot (puerto interno de desarrollo, actualmente 3100, accesible desde el LXC mediante la dirección de red verificada en el bootstrap).
- **Bootstrap UNA SOLA VEZ.** La instalación inicial de hosts, virtual host, CA/certificado local y reverse proxy se ejecuta, prueba y documenta **solo en el trabajo de puesta en marcha inicial**. **Después NO volver a comprobar proactivamente si está configurada, ni reconfigurarla, regenerar certificados, tocar `/etc/hosts`, inspeccionar LXC o reinstalar proxy por el mero hecho de iniciar OMP, MainSpot o una sesión nueva.** Arrancar la aplicación normalmente y utilizar directamente el dominio; probar la aplicación funcionalmente por esa URL. Investigar la infraestructura solo cuando se observe un error real de acceso o se solicite explícitamente una modificación.
- El upstream puede seguir en `localhost:3100` **solo como detalle interno del host**; no presentarlo como URL pública de desarrollo, no utilizarlo en el navegador E2E como bypass. Evitar fallback silencioso y nunca usar `ignoreHTTPSErrors` para esconder errores TLS.
- El certificado de confianza local se genera/instala solo inicialmente y no va al repositorio junto con claves privadas. Ninguna modificación productiva; proveedores Google/Meta/Telegram mantienen su simulación hasta su verificación real.
- Persistencia: este archivo `.omp/RULES.md` es la **regla sticky del proyecto OMP**; vale para sesiones nuevas. Mantenerlo en el repo y conservar estas reglas en futuras modificaciones. No confiar solo en resumen de chat o en memory backend opcional.
