# FR-0012 — MainSpot AI Core: un asistente, catálogo de casos de uso y Jev como clasificador primario

## Statement
El dueño trata con **un solo asistente** (panel, Telegram y canales autorizados). Internamente cada operación de IA
pertenece a un **caso de uso registrado** (`use_case_id`) con prompt versionado, ruta de modelo versionada,
presupuesto y política propios. Ningún caso de uso existe por permiso implícito del modelo: se incorpora al
catálogo, se evalúa y se activa.

Jev (TypeSafe System One) es el **clasificador semántico primario** de mensajes y eventos de texto: intención,
capacidad destino, sentimiento (positivo / neutral / negativo / mixto), categoría, urgencia, señales de riesgo,
necesidad de aclaración e incertidumbre. Jev **no genera, no autoriza y no ejecuta**: identidad, tenant, RBAC,
cuotas, aprobaciones y publicación quedan en el backend. La confianza de Jev no se trata como probabilidad
calibrada salvo evaluación que lo demuestre.

## Acceptance criteria
| id | given / when / then |
|---|---|
| AC-12001 | Given un mensaje del dueño de un tenant autorizado para Jev, when llega al asistente, then la clasificación registrada proviene de Jev (fuente `jev`) y la acción se decide en backend. |
| AC-12002 | Given un tenant sin autorización de datos para TypeSafe, when llega un mensaje real, then no sale ningún dato y la UI/registro muestran `BLOCKED_EXTERNAL` para la clasificación semántica. |
| AC-12003 | Given una invocación de IA, when termina, then queda registrada con use_case, prompt_version, route_version, proveedor, modelo, latencia, uso/costo con origen y resultado de política. |
| AC-12004 | Given una petición sin caso de uso activo, when se intenta ejecutar IA, then se rechaza (deny-by-default). |
