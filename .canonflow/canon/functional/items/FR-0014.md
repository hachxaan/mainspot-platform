# FR-0014 — Acuse humano con botón «Confirmar recepción»

## Statement
Los avisos que exigen acuse (severidad error y TEST-SYNTHETIC) muestran un botón «Confirmar recepción». Solo una pulsación del usuario autorizado, en el chat autorizado, sobre un mensaje enviado para ese evento y con datos de callback auténticos produce un acuse; se persiste de forma durable, idempotente y auditable antes de dar por procesada la actualización, y el bot confirma visiblemente al usuario. Los avisos meramente informativos (avisos de advertencia) no llevan botón.

## Acceptance criteria
| id | given / when / then |
|---|---|
| AC-9141 | Given un callback válido, when se procesa, then el evento pasa a human_acknowledged con un único registro de auditoría. |
| AC-9142 | Given actor, chat, mensaje o firma distintos, o evento inexistente, when se procesa, then se rechaza sin transición. |
| AC-9143 | Given callbacks duplicados o un fallo entre persistir el acuse y avanzar el cursor, when se reprocesa, then no hay pérdida ni doble acuse. |

## Notes / rationale
Mandato SRC-0011 (botón y acuse); DEC-0065 exige confirmación personal antes de producción. PROPOSED hasta G-FUN.
