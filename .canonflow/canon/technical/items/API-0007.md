# API-0007 — Registro durable de avisos y máquina de estados

## Statement
**Raíz:** `ALERT_STATE_DIR` (absoluta, sin `..`), por defecto `$HOME/.local/state/mainspot/alerts`. Directorio del usuario, sin enlaces simbólicos, modo sin bits de grupo ni otros; se crea con 0700.

**Contenido:**
- `events/<event_id>.json` (0600, escritura atómica: temporal → `fsync` → `rename` → `fsync` del directorio);
- `cursor.json` (`offset`, `last_poll_at`);
- `audit.jsonl` (solo anexado, `fsync`);
- `state.lock` (mutaciones breves; ninguna llamada de red con el candado tomado);
- `poller.lock` y `overdue.lock` (consumidores únicos).

**Registro del evento** (`schema: mainspot-alert-ack/v1`):
- evento validado sin secretos;
- `requires_ack`, `ack_capable`, `ack_unavailable_reason`, `deadline`, `state`, `in_flight`;
- `receipts[]` (`message_id`, `date`, `kind`: `initial` | `reminder` | `recovered`, `recorded_at`);
- `ack` (`at`, `message_id`, `update_id`, `actor_ref`, `late`);
- `reminders_sent`, `last_reminder_at`, `history[]` (`at`, `from`, `to`, `reason`).

**Transiciones permitidas:**

| Desde | Hacia |
|---|---|
| `created` / `send_failed` | `api_accepted`, `send_failed`, `api_acceptance_uncertain`, `misrouted` |
| `api_accepted` | `human_acknowledged`, `ack_overdue`, `needs_operator_attention` |
| `api_acceptance_uncertain` | `human_acknowledged`, `ack_overdue` |
| `ack_overdue` | `acknowledged_late`, `needs_operator_attention` |
| `needs_operator_attention` | `acknowledged_late` |

`misrouted`, `human_acknowledged` y `acknowledged_late` son terminales. Cualquier otra transición se rechaza; `send_failed` nunca pasa a `ack_overdue`.
