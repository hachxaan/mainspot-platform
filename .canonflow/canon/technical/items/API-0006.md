# API-0006 — Protocolo de acuse por callback (único consumidor `getUpdates`)

## Statement
**Modo:** `remote-alert-telegram.py --ack-poll [--max-seconds N]` (1 ≤ N ≤ 3600).
- Toma `poller.lock` con `flock` no bloqueante; con otro consumidor activo, salida `17`.
- Con `getWebhookInfo.url` no vacío o un 409, salida `17`.
- Long polling `getUpdates` con `offset` = cursor persistido y `allowed_updates=["callback_query"]`.

**`callback_data` (≤ 64 bytes):** `a1:<event_id 32 hex>:<etiqueta 24 hex>`, donde etiqueta = `HMAC-SHA256(clave_ack, "mainspot-alert-ack|v1|" + event_id)` truncada a 96 bits.
- La clave de acuse es exclusiva (`~/.config/mainspot/backup/telegram-ack.key`, 0600, directorio no accesible por otros, ≥ 32 bytes aleatorios en hex) y **no** es el token.
- La verificación usa `hmac.compare_digest`.

**Aceptación: se exigen todas las condiciones**, en este orden y sin transición si falla alguna:
1. tipos válidos y `callback_query.message` presente;
2. formato de los datos y firma;
3. `from.id` = usuario autorizado (`TELEGRAM_ACK_USER_ID`, o el chat si es privado y positivo) y `from.is_bot = false`;
4. `message.chat.id` = chat configurado;
5. evento existente con `requires_ack` y `ack_capable`;
6. `message.message_id` entre los recibos del evento y `message.date` igual a la fecha de ese recibo.
   Excepción: un evento `api_acceptance_uncertain` sin recibos recupera el recibo desde el callback (`kind=recovered`).

**Transiciones:**

| Estado del evento | Resultado del acuse |
|---|---|
| `api_accepted`, `api_acceptance_uncertain` antes del plazo | `human_acknowledged` |
| Pasado el plazo | `ack_overdue` registrado con su instante y después `acknowledged_late` |
| `ack_overdue`, `needs_operator_attention` | `acknowledged_late` |
| Ya acusado | Duplicado idempotente, sin cambio |

**Orden de persistencia:** acuse o rechazo en el registro y en la auditoría → cursor `update_id + 1` → respuesta de interfaz (`answerCallbackQuery` y eliminación del botón con `editMessageReplyMarkup`), de mejor esfuerzo. Una caída antes del cursor implica redelivery idempotente.

**Auditoría:**
- se guarda `actor_ref` = HMAC(clave_ack, `"mainspot-alert-ack|actor|" + from.id`) truncado a 64 bits; nunca ids en claro;
- los rechazos registran el motivo y no registran datos no autenticados.
