# API-0008 — Vencimiento, recordatorios acotados y estado observable

## Statement
**Política** (obligatoria para `ack_capable`; sin valores de producción en este desarrollo):

| Clave | Rango |
|---|---|
| `ACK_DEADLINE_SECONDS` | 60…604 800 |
| `ACK_REMINDER_INTERVAL_SECONDS` | 60…604 800 |
| `ACK_MAX_REMINDERS` | 0…10 |

**`--check-overdue`** (con `overdue.lock`):
- `api_accepted` / `api_acceptance_uncertain` con `ahora ≥ deadline` → `ack_overdue`;
- en `ack_overdue`, un recordatorio por intervalo hasta `ACK_MAX_REMINDERS`, con un tope global de 5 por ejecución:
  - el recordatorio es un mensaje nuevo, primera línea `ID: <event_id>`, `RECORDATORIO n/max` y el mismo botón;
  - su recibo se añade como `kind=reminder`;
  - cada intento cuenta para el tope;
- agotados los recordatorios y pasado un intervalo más → `needs_operator_attention`;
- un recordatorio mal dirigido detiene los recordatorios y pasa a `needs_operator_attention`.

**`--status`:** JSON sin secretos con el recuento por estado, los eventos sin acuse (`event_id`, `code`, `state`, edad, tiempo hasta el plazo) y la última consulta del consumidor.
- El consumidor cuenta como `stale` si nunca consultó o lleva más de `ACK_DEADLINE_SECONDS` sin hacerlo.
- **Salida `18`** si hay eventos en `ack_overdue`, `needs_operator_attention`, `send_failed`, `api_acceptance_uncertain` o `misrouted`, o si hay acuses pendientes con el consumidor `stale`.

**Reloj:** UTC del sistema. `MAINSPOT_ALERT_LAB_NOW` solo existe para pruebas; el productor nunca la propaga, porque pasa al adaptador solo `PATH` y `HOME`.

Ninguna cadencia (temporizador o servicio) se instala ni se activa en este desarrollo.
