# API-0009 — Integración con el productor (`db-backup-remote.py`)

## Statement
**Traducción de salidas del adaptador a `delivery=`:**

| Salida | `delivery=` |
|---|---|
| 0 | `ok` |
| 10 | `failed-not-configured` |
| 11 | `failed-config` |
| 12 | `failed-invalid` |
| 13 | `failed-unavailable` |
| 14 | `failed-misrouted` |
| 15 | `failed-acceptance-uncertain` |
| 16 | `failed-receipt-untracked` |
| Timeout del subproceso | `failed-timeout` |

**Reintentos:**
- Solo se reintentan desde `remote-alerts-pending/` (DEC-0065, 24 intentos / 72 h): `failed-unavailable`, `failed-not-configured`, `failed-config`, `failed-integrity`, `failed-exec` y `failed-rcN`.
- `failed-misrouted`, `failed-acceptance-uncertain`, `failed-receipt-untracked` y `failed-timeout` no se reintentan, porque podrían duplicar el mensaje. Pasan a `remote-alerts-failed/` con `needs_operator_attention=yes`.

**Registro del productor:** la línea `status=ALERT` añade `message_id` y `ack` del recibo del adaptador cuando existen. El productor nunca escribe `human_acknowledged`.

El límite E-SIZE-LIMIT previo a S3, la integridad del adaptador y el resto del contrato 1.2.0 no cambian.
