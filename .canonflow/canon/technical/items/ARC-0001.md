# ARC-0001 — Arquitectura del AI Core: registro, despacho con versión fijada y adaptadores

## Statement
Módulo `src/ai/` dentro del monolito TypeScript/PostgreSQL existente; sin framework multiagente. Capas:

1. **Registro en BD** (DAT-0001): casos de uso, proveedores (con *referencia* a secreto), modelos por ID exacto con
   precio y fecha de origen, revisiones de prompt inmutables, revisiones de ruta (modelo + revisión de prompt +
   parámetros) con ciclo de vida, rollout por caso de uso (activa + canary %), suites y ejecuciones de evaluación.
2. **Despachador** (`AiDispatcher.invoke`): resuelve el rollout **en el momento de iniciar**, elige activa o canary
   por hash estable (`use_case_id`, clave de asignación) < porcentaje, y **fija** `route_id`/`prompt_revision_id` en la
   fila de invocación. Un job multi-paso guarda sus rutas fijadas al crearse; cambios de rollout posteriores no lo
   afectan. Orden: política de datos → presupuesto (reserva) → render del prompt → proveedor con deadline →
   validación de salida (1 reparación como máximo) → registro de uso/costo → resultado.
3. **Render de prompt**: preámbulo de plataforma (no editable) + system + task con variables `{{nombre}}` de lista
   blanca y tipo declarado; el contenido no confiable va JSON-codificado dentro de delimitadores
   `<<<DATOS_NO_CONFIABLES ... >>>`. Variable desconocida o de tipo distinto ⇒ error antes de llamar.
4. **Adaptadores directos** (`src/ai/providers/`, DEC-0069): `anthropic` (Messages API; salida estructurada con
   `output_config.format` json_schema y, si el esquema excede los límites del proveedor, herramienta única como
   respaldo; herramientas del asistente), `openai` (Images API con `gpt-image-2`; Responses API con `store:false` solo
   si se evalúa texto), `typesafe` (Jev, cliente existente), `simulated` (determinista, etiquetado; solo pruebas).
   Ningún proveedor cobra a través de un intermediario: costo `estimated` = uso × precio publicado guardado en el
   modelo (los proveedores no informan el cargo por llamada). Un adaptador nunca cae a otro: el respaldo es otra
   **ruta** evaluada de un proveedor directo, explícita en la configuración; OpenRouter está retirado.
5. **Jev semántico** (`AiDispatcher.invokeClassification`, `src/engagement/ai-semantics.ts` y el intake
   existente): preguntas tipadas, presupuesto compartido DEC-0032 y política de datos DEC-0067.
6. **Herramientas del asistente**: funciones de lectura tipadas con tenant/actor de la sesión.
7. **Jobs durables** (`ai_job`): lease, reintento acotado, idempotencia por clave; worker integrado en el proceso
   del servidor (como el scheduler) o propio.

## Contrato de invocación
Entrada: `request_id`, `idempotency_key`, `tenant_id`, `actor_id`+rol, `origin`, `use_case_id`, entrada tipada
minimizada, `brand_facts_version`, `consent_ref`, `trace_id`, `deadline_ms`, `budget_usd` máximo.
Registro: `prompt_revision_id`+hash, `route_id`+versión, proveedor, modelo exacto, `policy_version`, estado,
validación, uso (tokens/imágenes), costo y su origen, latencia, error seguro.
Salida: `schema_version`, resultado estructurado o referencias, `validation`, `uncertainty`, `usage`, `safety`.
El modelo nunca recibe credenciales, ids de tenant ni decide permisos.

## Notes / rationale
Configuración dinámica en BD con lectura del rollout por invocación (una consulta indexada): consistencia inmediata
entre procesos sin caché distribuida. Reutiliza aprobaciones, versionado web, scheduler y auditoría existentes.
