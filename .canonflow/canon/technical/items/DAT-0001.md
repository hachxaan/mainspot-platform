# DAT-0001 — Modelo de datos del AI Core (migración aditiva 0025)

## Statement
Tablas nuevas, aditivas; ninguna columna existente cambia de significado.

| Tabla | Propósito | Invariantes |
|---|---|---|
| platform_user, platform_user_role, platform_session | identidad de plataforma separada de los negocios | TOTP cifrado (SecretBox, AAD propia); sesión con `mfa_at`, `step_up_at`; revocable |
| platform_audit_event | auditoría de plataforma | append-only (trigger) |
| ai_use_case | catálogo | id estable |
| ai_provider | proveedor directo (`anthropic`, `openai`, `typesafe`, `simulated`) y `secret_ref` (nombre, no valor); `real_data` (`blocked`/`allowed`) con `real_data_basis` y `terms_verified_at` | sin columnas de secreto; `allowed` exige base y fecha de verificación (0028); `openrouter` solo como historial y siempre `disabled` |
| ai_model | modelo por ID exacto, modalidades, precio con `price_source` y `price_observed_at` | — |
| ai_prompt_revision | system/task/variables/hash | contenido inmutable (trigger) |
| ai_route_revision | modelo + prompt + parámetros + estado de ciclo de vida | contenido inmutable; solo cambia `status` por transición válida |
| ai_rollout | activa/canary/% por caso de uso y entorno | `version` monotónica, escritura atómica |
| ai_rollout_event | historial | append-only; acción `retire` para rutas de proveedores retirados (0028) |
| ai_eval_suite, ai_eval_run | casos sintéticos y resultados | la ejecución referencia la ruta exacta |
| ai_invocation | traza y ledger de uso | única por (tenant, use_case, idempotency_key); sin texto completo de entrada |
| ai_budget | límites por ámbito/periodo | reserva bajo candado consultivo |
| ai_job | trabajos durables | lease + fencing por `claim_token` |
| brand_fact | memoria comercial versionada | append-only por clave; `brand_version` por negocio |
| media_asset | imágenes (bytea webp + variantes) | id aleatorio de 128 bits; tenant obligatorio |
| response_ledger | una respuesta pública por objetivo | UNIQUE(tenant, origin, target_ref) |
| marketing_campaign | planes propuestos | `spend_authorized` siempre false sin autorización externa |
| ai_insight, editorial_suggestion | resultados persistidos | con periodo/evidencia |
| client.data_classification | `synthetic`/`real` (default `real`) | cambio solo por platform_admin |

Retención: el job diario elimina `ai_invocation.output` y detalles de `validation` a los 90 días, sin borrar
uso, costos, modelo ni claves de idempotencia. También cubre evaluaciones de plataforma sin tenant. La
solicitud con contenido purgado no se reproduce como éxito vacío ni dispara un nuevo cargo con la misma clave.
